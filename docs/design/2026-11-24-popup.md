# `Popup`: what a control opens beside itself (2026-11-24)

Status: built. Ruled by the user 2026-11-24 ("yes go for popup -
implement and write design").

## Why

A crop screen has a button for the aspect ratio. A tap on it opens a
strip of six choices above the button; a tap on a choice, a second tap
on the button or the back key closes it.

In the first host of gogo that strip was a page of its own, placed over
the crop page by code. The code measured the strip, worked out where it
sits over the button, kept it inside the screen, drew it after the crop
page, asked it first for every finger, and closed it on back. The crop
page's file showed none of it: the button's line gave no sign that it
opens anything.

Every program writes that code again for every menu. And a page is the
wrong thing for it: a page has a file, a struct and a place in the back
stack, where a menu is a part of one control.

## The node

```kdl
View page {
    Check more width=60, height=50 {
        Label text="More"
        Popup menu side=top, align=end, visibility=gone {
            Column background=#2C2F38, padding=6, spacing=4 {
                Button about text="About"
                Button help text="Help"
            }
        }
        when selected menu.visibility = visible
    }
}
```

A `Popup` is written inside the node it belongs to. The file then shows
that the Check opens something, what, and on which side.

| Word | Says |
|---|---|
| `side=top\|bottom\|left\|right` | the side of the parent's rectangle it opens on. Required: there is no default (G7020). |
| `align=start\|center\|end` | where it sits along that side. Unwritten: centered. |
| the size words (`width=`, `max_height=`) | cap or fix its box. Unwritten: as big as what it holds. |
| `visibility=` | shows and hides it, as for any node. |

What gogo does with it:

- **Size.** That of what it holds.
- **Place.** Against the parent's rectangle on `side=`, at `align=`
  along it, then moved by the least that puts it inside the page's safe
  area. It follows its parent where layout or a Scroll moves it.
- **Above the page.** Drawn after every other node of the page, asked
  first for a finger, also where it lies outside its parent. No node
  between it and the root cuts, turns or fades it. It moves and fades
  with its page.
- **Beside it.** A finger beside a Popup goes to the page as before,
  and the Popup stays open.
- **Its parent's look.** A Popup is no part of it: a Check with only a
  Popup in it keeps its native mark, and is no bigger for it.

## Showing: no new word

A Popup shows and hides with `visibility=`. A new word (`open=`) would
have been a second way to say the same.

- `visibility=gone` on its line: closed until something shows it.
- `when selected menu.visibility = visible` in a Check: a tap opens it,
  the next tap closes it. No code.
- `when hovered`, `when held`: a hint while the mouse is over a button,
  or while a finger holds it.
- From code: `set_visible`.

While it is gone, it and what it holds take no part in layout.

## Back

A back request hides the topmost Popup that shows, and the page's code
is not asked. One rule, in the engine, for every Popup of every page.

gogo hides a Popup by ending what shows it:

| What shows it | What back does |
|---|---|
| a `when selected` of a control | the control is unselected and its `on:change=` raised, as a tap on it would |
| a write from code | the write is written back to `gone` |
| the file's own line, or a `when` of another state | nothing: the Popup under it is tried, then the page |

The topmost one is the last in the file that shows.

gogo has no back key. A host calls `Input::hide_top_popup` first and
asks its page only when that returns `None`. TurboDot does, in
`Program::back`, for the page on screen and the pages placed in it.

## A Popup is not a dialog

| | `Popup` | Dialog |
|---|---|---|
| Belongs to | one control of one page | nobody: any page can open it |
| Sits | against that control | in the window |
| What is under it | still usable | blocked |
| Its code | the page's own handlers | its own struct, file and handlers |

A dialog stays a page (`PageKind::Overlay` in TurboDot).

## How it is built

With what the engine already had; no new pass over the nodes.

- **Above the page: the seat table.** A `when` can move a node into a
  `seat`: the resolve keeps, per node, the parent it is placed under,
  and layout, drawing and the search for the node under a finger all
  read that. Every Popup is seated under the page's root, after the
  root's own children (`settle_seats`). That alone gives the draw
  order, the finger order and the freedom from its ancestors' cuts.
- **Size: an ordinary free child.** The compiler gives a Popup
  `halign=left, valign=top, overlay=true`. The root places it at the
  page's top left corner, as big as what it holds, and it sizes nothing.
- **Place: a move after layout.** `popup::seat_popups` runs in the
  frame road after layout: it moves the rectangles of each shown Popup,
  and of what it holds, to their place against the parent's rectangle.
  A move lays nothing out, so a Popup follows a parent that a Scroll
  pans at no cost.
- **Showing: `visibility=`.** Nothing built.
- **The list.** `Page::popups` names the Popups of a page. A page with
  none pays one length check where a frame seats them, one where a
  resolve settles its seats, and nothing in a frame that lays nothing
  out.

## Not built

- **A gap** between a Popup and its parent. What it holds can carry its
  own padding.
- **A flip** to the other side when there is no room. A Popup with no
  room covers a part of its parent.
- **Closing on a finger beside it.** The first host's strip stays open
  until a choice, the button or back closes it, and so does a Popup.
- **An event when back hides a Popup that code showed.** A control's
  `on:change=` is raised; a page that showed a Popup from code and must
  know reads its `visibility`.
- **A Popup whose parent is gone.** It is seated on the root, so it
  would show at the parent's last place. A file hides it with its
  control.
- **Poses inside a control.** An `arrangement` belongs to the whole
  page, so a control with poses cannot be used twice in one page. That
  is why the first host has small pages where it wants controls. A
  design of its own.
